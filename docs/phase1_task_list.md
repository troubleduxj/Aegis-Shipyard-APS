# Aegis Shipyard APS & Command 阶段一（MVP）落地实施任务清单 (Actionable Task List)

本篇任务清单将阶段一（MVP）的落地过程拆解为 **4 个核心工作包 (Work Package)** 暨一系列极具实操性的原子任务（Scrum Task）。可直接导入 Jira、Trello 或飞书项目看板。

---

## 工作包一：数据持久化底座开发 & 数据库建表 (DB & Storage)
*   **研发周期**：第 1 周（第 1-3 天）
*   **负责人**：DBA / 后端工程师

| 任务 ID | 任务名称 | 任务描述 | 交付物/验收标准 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| **TSK-101** | SQLite3 本地环境部署及多平台适配 | 在 NodeJS 后端项目中配置 `sqlite3` 及 `knex` 或 `sqlite` 轻量级 ORM 库，确保在开发/测试容器及本地 Windows 环境下免打包编译通过。 | `npm init` 依赖中包含本地 SQLite 核心驱动，建立 `database.sqlite` 本地存储。 | P0 |
| **TSK-102** | 核心数据表 Schema 迁移配置及初始化 | 编写 SQL 迁移脚本，创建 `sys_docks` (船坞设施)、`shipyard_projects` (船舶母表)、`project_stages` (工序计划) 与 `telemetry_logs` (中控日志) 四张表。 | 执行 `npm run db:migrate` 可直接于本地干净环境重建无错表结构。 | P0 |
| **TSK-103** | 标杆厂基础数据（Seed Data）导入 | 导入真实的造船厂配置初始化数据（如 Dry Dock 1, Outfit Quay 3 的物理尺寸、LNG/Bulk Carrier 的典型六大建造阶段工序）。 | 数据库中预置不少于 4 个大型泊位和 3 个在建船舶工程。 | P1 |

## 工作包二：排程约束求解引擎 (APS Engine Implementation)
*   **研发周期**：第 1 周至第 2 周（第 4-8 天）
*   **负责人**：算法工程师 / 后端开发

| 任务 ID | 任务名称 | 任务描述 | 交付物/验收标准 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| **TSK-201** | 拓扑依赖排序算法 (CPM Logic) | 编写关键路径法 (CPM) 中的拓扑排序函数，确保船舶的不同建造阶段（如“钢板切割”必须绝对领先于“合拢 assembly”）具有严格的时间前置依赖。 | `cpmTopologySort(tasks)` 单元测试通过，能检测并拒绝循环依赖工序。 | P0 |
| **TSK-202** | 2D 二维空域装箱寻优函数开发 | 落地“空间-时间联合装箱算法”。对每个被排程的任务，检测特定时间段内是否有满足其长宽规格的连续船坞物理区段（1D 长度滑轨 + 1D 宽度拼幅）。 | `allocateDockSpace(registry, dockId, day, taskLength)` 完成，避免船坞拼图发生物理重叠。 | P0 |
| **TSK-203** | 班组人力波峰约束平滑器 | 面向全厂最紧缺资源（如持证高级特种焊工）进行每日累计用工上限限制。当预测出现尖峰负荷时，算法自动延后非关键路径项。 | 支持 `resourceCap` 约束校验，输出每日厂区人员负载水平曲线数据（JSON）。 | P1 |
| **TSK-204** | 算法在极端负荷下的压力测试套件 | 编写测试脚本，向求解器输入大于 50 艘大型船舶在 2 个狭窄船坞的排程任务，测试求解引擎是否能在 2 秒内优雅给出部分无法调度排产的提示。 | 运行 `npm run test:aps` 执行无内存泄露的压力测试。 | P2 |

## 工作包三：智能提问、事件 Grounding 与控制反写 (AI Engine & API)
*   **研发周期**：第 2 周（第 7-11 天）
*   **负责人**：AI 开发工程师 / 全栈工程师

| 任务 ID | 任务名称 | 任务描述 | 交付物/验收标准 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| **TSK-301** | Gemini 2.5 Flash SDK 企业账号集成 | 注册并对接 Google Gemini API，在 Server 端通过 AI SDK 封装安全调用。严禁在前端暴露秘钥明文。 | 搭建服务端专属 `/api/ai/command` 骨架接入路由，环境配置中新增 `GEMINI_API_KEY`。 | P0 |
| **TSK-302** | 提示词工程 (Prompt Schema) 固化 | 设计 System-level Role Prompt。强制模型接收到口语指令时（如“滑道大风故障，全员停工两小时”），仅输出标准 JSON 格式参数。 | 通过端对端测试：输入突发状态语句，LLM 成功抽取出结构化的 `action`, `adjustmentPercentage` 字段。 | P1 |
| **TSK-303** | 求解算法的触发与数据库持久化反写 | 当 AI 解析到调整动作（如因为台风，将“分段合拢”工期延迟 3 天）时，自动修改 SQLite 中对应的 `duration_days`，并触发算法模块全量重排写库。 | 数据库中对应的 `plan_start_date` 与 `plan_end_date` 完成级联调整并留档。 | P0 |

## 工作包四：一屏式多维甘特图 & 指挥控制台 (Frontend SPA UI)
*   **研发周期**：第 2 周至第 3 周（第 10-14 天）
*   **负责人**：前端开发工程师

| 任务 ID | 任务名称 | 优先级 | 任务描述 | 交付物/验收标准 |
| :--- | :--- | :--- | :--- | :--- |
| **TSK-401** | 响应式多功能甘特图/时间轴重构 | 利用当前已完成的高级界面骨架，实现多船舶、多维度（左侧船坞索引，上方时间轴，中间甘特进度条）的高效数据联动渲染。 | 甘特图支持横向无限平滑滚动、日期粒度切换（天/周/月/年）。 | P0 |
| **TSK-402** | 可折叠指挥控制台组件化重整 | 对下方的“实时事件跟踪看板”与“AI 指挥台”开发一键轻量化交互折叠栏部件。默认不占用排程图表的纵向显示黄金区域。 | 用户点击“点击展开 AI & 日志监控”时，该面板向下滑入/展开，不发生页面闪烁与卡顿。 | P0 |
| **TSK-403** | 手动模拟广播与 WebSocket 状态上屏 | 强化中控大屏的“广播”和“提问”功能细节，支持调度室手动发布物流中断、班组交接班，一秒内将数据无感渲染至活动日志窗。 | 输入模拟事件，实时跟踪看板立即刷新展示最新的 info/success/warning 标签。 | P1 |
